## PathOS — Healthcare application

Personal project for **patient-record management and assistance with medical report preparation**. Currently in **pre-pilot testing**, with physicians' feedback guiding functional improvements.

**Stack:** **Python / FastAPI** backend, **React / TypeScript** frontend and **PostgreSQL** database. Document recognition with **PP-OCRv5 / PaddleOCR**; speech transcription with **Parakeet v3, quantized to int8**, running through **sherpa-onnx**. Both processing engines support CPU inference to accommodate the available hardware.

**Engineering approach:** document and voice processing, structured extraction, deterministic report generation, human review and change traceability. Verification combines automated tests and user-journey checks.

**My role:** requirements, technical choices, component integration and remote maintenance, working with physicians and the laboratory's IT contact. Changes are checked on a test instance before release, with fixes handed over to the laboratory.

*Private source code; this public overview is limited to objectives, main technologies and development practices. Related private R&D includes VoxPath (voice processing) and ScriptPath (document processing).*

## How I work with AI agents

I configure and operate a personal development environment around **Hermes**. The setup below supports project planning, implementation and maintenance.

| Component | Technical setup and practice |
|---|---|
| **Infrastructure** | Hermes on a continuously running **Linux VPS**; access to development workstations through **Tailscale + SSH**. |
| **Project context** | **Telegram**, with one bot per major project and dedicated settings, conversation context and memory. |
| **Persistence** | Memory stored on the VPS SSD, with **Google Drive backups** for continuity across sessions. |
| **Planning** | **ChatGPT / Codex** for framing and planning; direct planning in Hermes when detailed project context is needed. |
| **Models & orchestration** | **OpenAI** and **DeepSeek** models, selected by task complexity and token budget. Where enabled, **Astra** acts as an orchestrator and selects sub-agents. |
| **Implementation & checks** | Coding, diagnostics and tests on workstations or the VPS. Depending on the project: **pytest**, **Vitest**, **Playwright**, type checks, linting and manual checks. |
| **Delivery** | Test-instance verification and user feedback before live changes; reports and **SHA-256 manifests**, with Drive publication checked by rereading uploaded files. |
| **My responsibility** | Define scope, choose technical trade-offs, review results and approve changes. |

### PathOS — Application métier en santé numérique

Projet personnel consacré à la **gestion des dossiers patients et à l'assistance à la préparation de comptes rendus médicaux**. Actuellement en **phase prépilote**, avec des essais et des retours de médecins pour orienter les évolutions fonctionnelles.

**Stack technique :** backend **Python / FastAPI**, interface **React / TypeScript**, base de données **PostgreSQL**. Reconnaissance documentaire avec **PP-OCRv5 / PaddleOCR** ; transcription vocale avec **Parakeet v3 quantifié int8**, exécuté via **sherpa-onnx**. Moteurs compatibles CPU, adaptés aux contraintes du matériel disponible.

**Principes de conception :** traitement documentaire et vocal, extraction structurée, génération déterministe de comptes rendus, revue humaine et traçabilité des modifications. Vérification par tests automatisés et essais des parcours utilisateurs.

**Mon rôle :** cadrage métier, choix techniques, intégration des composants et maintenance à distance, en coordination avec les médecins et l'informaticien du laboratoire. Les changements sont vérifiés sur une instance de test avant mise en service, puis les correctifs sont transmis au laboratoire.

*Code source privé ; présentation limitée aux objectifs, aux technologies principales et à la démarche de développement. Les travaux de R&D privés associés comprennent VoxPath (traitement vocal) et ScriptPath (traitement documentaire).*
